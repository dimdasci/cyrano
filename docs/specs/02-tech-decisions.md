# 02. Technical decisions

Status: agreed 2026-10-27. Revised the same day: local models (Apple Foundation Models, MLX) were rejected on quality, and the only engine is models through the ChatGPT subscription. The history of the comparison: [04](04-prompts.md) §3.

## Platform and stack

| # | Decision | Rationale |
|---|---|---|
| T1 | macOS 27+, Apple Silicon | The user's current system, no regard for older versions |
| T2 | Swift 6.4 compiler, Swift 6 language mode, strict concurrency; SwiftUI for the UI, AppKit for `NSPanel`, the status bar and AX | SwiftUI can't do non-activating floating panels |
| T3 | Repository: `App/` — the app's Xcode project (UI, AX, hotkeys, windows); `Packages/CyranoCore/` — a local Swift Package (OpenAI client, authorization, prompts, diff, dictionary, settings); `docs/` — the spec and wireframes; `evals/` — the example set and the runner. The app depends on CyranoCore | The core is tested with `swift test` without UI; UI code isn't mixed with logic |
| T4 | No App Sandbox, distribution outside the App Store. Until there is a Developer ID, the app is built locally and signed with a local self-signed certificate ([releases](../releases.md#distribution)) | The Accessibility API for other apps is incompatible with the sandbox. Without a stable signature macOS resets the Accessibility permission on every rebuild |
| T5 | `LSUIElement`: an agent in the menu bar, no Dock icon | A utility that's always at hand |
| T6 | One shortcut of its own, the global "Check text" (⌥⌘G by default), configurable in onboarding and Settings (the SPM package `KeyboardShortcuts` by sindresorhus). Inside the panel there are no shortcuts of its own, only system ones: Esc, Tab, ↩, ⌘C, ⌘V | Shortcuts you can't see and don't remember only confuse; everything in the panel is done with buttons. `KeyboardShortcuts` gives a ready UI for recording a hotkey and is the only external dependency. Version ≥ 3.1.0 is needed: in 1.x, while a menu was open, the library took all events off the queue and put them back, the menu item's action came late, and macOS refused to activate Cyrano, so Settings and About opened behind another app |
| T7 | The engine is the models of the ChatGPT subscription through Sign in with ChatGPT ([research](../research/openai-sign-in-with-chatgpt.md)). No API key and no local models | The only option with the quality we need: `gpt-6.1-sol` 18/21 against 16/21 for Gemma 4 12B and 13/21 for Apple on-device ([04](04-prompts.md) §3). Local models fix errors but don't make the text natural, and that's the main value |
| T8 | The engine sits behind the `CorrectionEngine` protocol in `CyranoCore`. The only implementation is `OpenAIEngine` | Tests with a fake engine, API isolation |
| T9 | Open source, MIT license. Author: Dim Kharitonov. Repository `github.com/dimdasci/cyrano`, documentation in the README and on GitHub Pages (`dimdasci.github.io/cyrano`); the About window links to them | Matches the self-serve access of Sign in with ChatGPT for open-source and local apps |
| T10 | The name is Cyrano, spelled as in the original. A reference to Cyrano de Bergerac, who wrote letters for someone else. The core is `CyranoCore` | An assistant with style who helps say things clearly and beautifully. The name is recognizable, and in English "cy" reads as "s", so we keep the spelling |

## Authorization

| # | Decision |
|---|---|
| A1 | Self-serve flow for local apps: `client_id=dynamic_agent_client` on the first sign-in, then the issued `oaiapp_…`; a stable `ext_agent_host_id` (`urn:uuid:…`); `agent_name_hint` = the app name |
| A2 | Authorization code + PKCE (S256), `state`, `nonce`. Sign-in in the system browser, callback on the loopback `http://127.0.0.1:1457/auth/callback` (`NWListener`) |
| A3 | Scope `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, `resource=https://api.openai.com/v1`. After the exchange we check that `chatgpt.tokens.use.direct` was granted |
| A4 | ID token: RS256 signature against the JWKS from `/.well-known/openid-configuration`, `iss`, `aud` = the issued client ID, `exp`, `nonce` |
| A5 | Tokens in Keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`), saved by updating the item in place. Refresh 2 minutes before expiry; the refresh token rotates and is replaced together with the access token. If the Keychain refuses the new tokens (a new build without access to the item), they stay in memory, since the old refresh token is already spent, and the request fails with an error that asks to allow access. Every next request tries to save them again and fails the same way until a save succeeds |
| A6 | Sign-out: revoke the refresh token through `revocation_endpoint`, delete the Keychain item |
| A7 | The "Continue with ChatGPT" button per OpenAI's guidelines. The sign-in screen shows on first launch and after access is revoked |

A1–A7 are implemented in [CyranoCore/Auth](../../Packages/CyranoCore/Sources/CyranoCore/Auth); the prototype from `evals/cloud-runner` was removed in package 17.

## Model

| # | Decision |
|---|---|
| M1 | Three models: `gpt-6.1-sol` (quality), `gpt-6.1-terra`, `gpt-6-luna` (faster, 17/21). The model is chosen in Settings → General separately for three operations: reading context from a screenshot (C6, Terra by default: the user waits for it before Check, and on the package 19 eval Terra and Sol read every case right, Luna sometimes returns only the name, and Terra never took more than 10 s; decided 2026-11-06, Luna before), the check and the dialog (Sol by default), explanations (Sol by default). The list is fixed in the app, we don't call `GET /v1/models`: new models are tested on the eval first, then added in a release. `gpt-6.1-luna` isn't available on the subscription (400 `model_not_found`). A saved model that's no longer in the list is replaced with the default. The 0.4 choice (one model for everything) becomes the check model |
| M2 | `POST /v1/responses`, `store: false`, `stream: true` (SSE). Success only on `response.completed`. `reasoning.effort = low` |
| M3 | Pipeline ([04](04-prompts.md) §2): Fix streams its reply by a schema (`text.format = json_schema`: `kind`, then `text`), we compute the diff ourselves (word-level LCS, adjacent changes are merged), Explain is a separate call with `text.format = json_schema` (category + reason per change number) |
| M4 | Dialog (S1a): the history is kept in the app and sent whole in `input` on every turn, because `previous_response_id` isn't supported in this mode. With our volumes the model's context (500k tokens) doesn't overflow, so compaction isn't needed |
| M5 | A dialog turn is one Fix call: the model judges what the author wants and replies with a new version or an answer, by the schema's `kind` ([04](04-prompts.md) §4.3). The first check and a recheck allow only a version. The app numbers the versions itself, Version 1 being the first check, and every version in the history carries its number (decided 2026-11-06; until package 20 a separate classifier call decided between a question and an edit) |
| M6 | Unsupported fields aren't sent: `temperature`, `max_output_tokens`, `metadata`, `previous_response_id`, `system` messages (only `instructions`) |
| M7 | Output language: by default the language of the conversation from Context ([04](04-prompts.md) §4.5), whatever the draft's language: the pop-up in the panel header switches to it before Check. If Context wasn't read or the language isn't in the list, it's the same as the source text (the model detects it). The user changes the language in the pop-up; the choice applies to this panel only and isn't remembered for the app (decided 2026-11-03: people write in different languages in the same app). There's no separate setting in Settings. If the target differs from the text's language, the model translates and corrects at the same time. Explanations of changes are in the interface language (05 §6), one short line; the `style` category separates changes of taste from errors |
| M8 | Prompts are editable. Instructions are assembled from blocks: base role + dialog protocol + text type (Message/Email/Docs) + tone + level of intervention + `{language}` + custom instructions. All blocks and pipeline calls (Proofread, Explain Changes, Read Context) are shown in Settings → Prompts; the user's version is stored on top of the built-in one (`prompts.json` in Application Support), and "Restore Default" brings back the built-in one. The user's text, context and dictionary go only into `input` |
| M9 | The Context field in the panel: free text (usually a pasted copy of the message I'm replying to). It's passed in `input` in a `<context>` tag; the instructions say it's material to read, not to correct or copy ([04](04-prompts.md) §4.2) |
| M10 | Images as context: 📷 captures the active window of the source app (ScreenCaptureKit); you can also paste an image (⌘V) or drag a file in. There is no hard limit; after 10 there's a warning about speed and limit usage. Each image goes as a separate `input_image` in the first message, at its original resolution, and, like the whole history, in every following turn; nothing is saved to disk |
| M11 | The "Never change" dictionary: a separate file `~/Library/Application Support/Cyrano/dictionary.json` — an array of `{"term", "added"}`, the date in ISO 8601, designed for hundreds and thousands of terms. It's read on launch and written whole (atomically) after every change; a file that can't be read is renamed to `dictionary.json.bak` so the terms aren't overwritten. Terms are unique case-insensitively. It's filled from the panel (selection → Never Change, or from a change row) and in the Settings → Dictionary tab with search, import and export. Only terms found in the source text go into the request: case-insensitive, on word boundaries (the neighboring character is neither a letter nor a digit), in order of appearance. Terms the text seems to misspell (a letter off, two for long terms) go too, as a spelling hint ([04](04-prompts.md) §4.2). If we need to keep a history of checks, move to SQLite (decided 2026-10-29: JSON for now) |
| M12 | The indicator in the panel: how many tokens the current dialog has used (`usage` from `response.completed`) and the subscription limit state. The errors `subscription_sharing_usage_limit_exceeded` and `subscription_sharing_usage_unavailable` are shown as a clear message |
| M13 | Errors and delays: a progress indicator, a 30 s timeout with one retry, on an error the source text isn't lost ("Copy original"). The timeout counts the response's events, not bytes: text, completion, errors and any other event of the response (`response.created`, `response.in_progress`, reasoning, output items) are progress; `keepalive` events, SSE comments and blank lines aren't. The request's own timeout counts bytes, and keep-alives are bytes: in the package 20 eval, Sol's first four parallel cases waited 398 s in one run and 60–63 s in another before their text came, and one Explain call failed after 905 s, with no timeout. A local test showed why: URLSession times out a started stream 5 s after the last byte with a 5 s timeout, and an SSE keep-alive every second keeps it open indefinitely; the openai-node SDK handles `keepalive` events in Responses streams, so these keep-alives were most likely events of that type. No raw stream was logged, so this is the likely cause, not a recorded one. 30 s holds for a healthy call: of about 3,300 turns in package 20's runs, apart from those stalls the longest took 36.5 s, and that was a check with two calls, Fix and Explain; a turn with one call never took over 30 s. A network error or a timeout is retried once if no text has arrived yet; after text it fails, so the text isn't shown twice. Without network, a clear message; there's no local fallback engine |

## Text capture and result

| # | Decision |
|---|---|
| C1 | Priority: selected text → the whole value of the field |
| C2 | Reading goes down a chain, without guessing: AX (`kAXSelectedText`/`kAXValue`); for Chromium/Electron we turn on `AXManualAccessibility`/`AXEnhancedUserInterface` and look for the focused field inside the page → emulated ⌘C, that is, only an explicit selection; if files ended up on the clipboard instead of text (Finder), there's no text. We don't press ⌘A and don't read the draft from a screenshot: the app doesn't change the selection in someone else's window and doesn't take text the user didn't choose. If nothing worked, the panel opens with an empty "Text to check" field: the user types or pastes the text |
| C3 | The result is only copied to the clipboard (Copy), and the user pastes it. There's no automatic insertion: there are too many places and ways to insert (a field, a selection on a page, editors, web apps), and writing through AX or ⌘V too often fails silently |
| C4 | We remember the app and the field's frame at the moment of the call: from them the panel labels the source, picks the settings and positions itself next to the field |
| C5 | Permissions onboarding: Accessibility is required. Screen Recording is optional, needed for 📷 and context reading (C6); both permissions are visible in Settings → General → Permissions. The app asks for Screen Recording only on an explicit action: 📷, the button in onboarding or in Settings; context reading only checks it (`CGPreflightScreenCaptureAccess`) |
| C6 | Context from a screenshot. If the text was read from an app window (C2), the app captures that window and with a separate call ([04](04-prompts.md) §4.5, model from M1) gets a description of the conversation: who it's with, the language, what it's about, the format, the style and how formal it is, without copying messages from the screen. The answer is fields by a schema; from them the app builds the lines of the Context field and puts the conversation language into the output language pop-up (M7). The result is plain text in the Context field: it's visible and can be edited before Check; the screenshot itself doesn't go into Fix, because a history with an image is expensive on every turn. No text from a window (desktop, Finder, Check Text…, Check Clipboard) means no screenshot. A 20 s timeout without a retry: an answer usually arrives in 3–6 s, but roughly one in eight takes 10–17 s ([04](04-prompts.md) §5). While reading is going on, Check waits; the user can skip reading (Skip) or start typing in Context, and the call is cancelled with no retry. A timeout, an error, an answer off the schema or no conversation on the screen leave Context empty, and next to the Context title it says why; after a timeout or an error the same screenshot can be read again ([05](05-ui.md) §2.3a). Without Screen Recording, automatic context reading doesn't run: only manual input and copy-paste (decided 2026-11-06). The app takes no screenshot, makes no call, shows no status and doesn't ask for the permission; the Context field stays empty for typing, ⌘V and dropped images. It's turned off in Settings → General. The call's tokens count towards the shared counter (M12) |

## Storage and privacy

| # | Decision |
|---|---|
| S1 | Settings in `UserDefaults`: the per-app panel options, custom instructions, models, toggles, the hotkey. The dictionary is a JSON file in Application Support (M11), the user's prompts will be one too (M8). Tokens only in Keychain |
| S2 | The MVP doesn't keep a history of checks. Context type, tone and level are remembered separately for each app (bundle id); the output language isn't (M7) |
| S3 | Text, context and screenshots go only to OpenAI (`store: false`). No telemetry or text logs of our own |

## Testing

- `CyranoCore`: unit tests for the diff, prompt assembly, SSE and error parsing, PKCE/JWT validation (on fixtures).
- The `cyrano-eval` eval on the app's code: fixes ([evals/fix](../../evals/fix/README.md)) and context reading ([evals/context](../../evals/context/README.md)) for prompt regression (04 §5). Before every prompt change, a run on the models from M1.
- A manual capture checklist: Safari, Chrome, Slack, Telegram, Mail, Notes, Messages.
