# 05. UI

Status: draft, reviewed against the Apple HIG 2026-10-27 (§8). Scenarios: [03](03-mvp-scope.md), technical decisions: [02](02-tech-decisions.md), wireframes: [../wireframes](../wireframes/README.md).

## Principles

- Function over effects. No animations except system ones. No pop-up hints on top of other apps.
- One shortcut. The global hotkey opens the panel; inside are buttons, Tab and system keys, with no shortcuts of its own, so there's nothing to remember (02 T6).
- The other app's window keeps input focus until it has to give it up. The panel is an `NSPanel` (`.nonactivatingPanel`). It takes focus only on a click in the dialog field or in Context.
- A system look. SwiftUI + standard controls, semantic system colors and fonts, light and dark themes.
- Meaning never rests on color alone. Every color difference is backed by a shape: strikethrough, underline, an icon, a group heading.
- Writing Tools in macOS as the reference point. Apple's system feature solves a similar task (proofreading on top of any app, a "Describe your change" field), so in disputed places we repeat its behavior.
- The user's text isn't lost. On any error the source stays available for copying.

## 1. Onboarding

One window with four sections (`Form`, `.grouped`), all visible at once, without a step-by-step wizard and without scrolling: that way it's easier to go back to any item, and there are only four steps. At the bottom, a "Done" button. The window opens on first launch, on every launch while there's no sign-in or no Accessibility, and when the app is launched again while it runs (§4).

```
┌─ Cyrano ───────────────────────────────────────────┐
│ 1. Sign in                                         │
│   Cyrano uses your ChatGPT Plus or Pro plan        │
│   to check your messages.                          │
│   [ Continue with ChatGPT ]                        │
│   Your text is sent to OpenAI only when you run    │
│   a check. It is not stored.                       │
│ 2. Accessibility                                   │
│   Cyrano reads the text in the field you're …      │
│   Accessibility          [Open System Settings…]   │
│ 3. Context from the window                         │
│   Read context from the window            [on]     │
│   A screenshot of the window goes to OpenAI …      │
│   Screen Recording       [Open System Settings…]   │
│ 4. Shortcut                                        │
│   Check text                         [ ⌥⌘G ]       │
│   Show in menu bar                        [on]     │
│                                          [Done]    │
└────────────────────────────────────────────────────┘
```

1. Sign in. The "Continue with ChatGPT" button per OpenAI's guidelines → the system browser. While we wait for the callback: "Waiting for the browser…" [Cancel]. A successful sign-in: "Signed in as name@…". Errors:
   - declined in the browser → "Sign-in was cancelled." [Try Again];
   - no `chatgpt.tokens.use.direct` → "Your plan doesn't allow apps to use it. Plus or Pro is required.";
   - network / 5 min timeout → "Couldn't reach OpenAI." [Try Again].
2. Accessibility. One sentence on why: "Cyrano reads the text in the field you're typing in, so you don't have to copy it." The "Open System Settings…" button. The status updates by itself (polling `AXIsProcessTrusted` once a second) → "✓ Granted". Without the permission you can press Done: the clipboard mode works.
3. Context from the window. The same "Read context from the window" toggle as in General (§5), with the same caption. When it's on, below it is the Screen Recording status line with an "Open System Settings…" button: the permission is needed to capture the window (02 C6). When it's off, there's no line, and 📷 asks for Screen Recording on its first press (§2.3a).
4. Shortcut. The hotkey recorder field (⌥⌘G by default), the hint "Select text or put the cursor in a text field, then press the shortcut." and the "Show in menu bar" toggle (on).

Everything else is explained by TipKit tips in the panel itself on first use, one at a time: before the first check, Context ("Add who you're writing to"), then 📷 ("Capture this window", if there's a window), after the first check, the dialog field ("Ask or tell what to change"). A tip disappears for good once it's closed with ✕ or once the user does what it's about: Check, 📷, Send.

## 2. Proofreading panel

### 2.1 Position and size

- Width 520 pt, height by content, at most 70% of the visible screen height; beyond that only the feed scrolls. The panel grows and shrinks downwards, the top edge stays in place and doesn't go off screen. The size isn't changed by hand.
- The panel computes the height itself: everything except the feed has a fixed height, so it needs the layout height plus however much the feed lacks to show all its content. Only the panel controller changes the window, on the next turn of the event loop: if the window size is taken from AppKit content (`preferredContentSize`) or SwiftUI content (`NSHostingView` as `contentView`), a fractional height against a pixel-aligned window starts an endless layout, and the app crashes.
- Position: below the input field (bounds from AX), if the field is visible and there's enough room below it; otherwise above the field; otherwise in the center of the screen where the cursor is.
- The panel has a standard title bar with a short noun title and the source, "Proofreading — Slack", and a close button; no minimize/zoom buttons. It's dragged by the title. The position isn't remembered.
- It closes on Esc and on the ✕ button. A click elsewhere leaves it open: you can switch to the chat, copy the context and come back.
- A closed panel frees memory right away, together with the session, the versions and the context images; a new check starts with a clean panel.

The message between the versions is in Russian on purpose: the user can write in the dialog in any language ("how do I say more precisely that there are no untagged PRs hanging in Bitbucket now").

### 2.3 Header

- Source: the name of the app the text was taken from, in the panel title ("Proofreading — Slack"). For text typed or pasted in the panel, "Manual".
- Context type: Message / Email / Docs. Tone: Neutral / Casual / Friendly / Professional / Concise. Level: Errors Only / Fluency / Rewrite. These are small pop-up buttons, each as wide as its current value. Changing any value rechecks the latest version with the new settings and adds a new card to the feed. The values are remembered for the app (bundle id). While a check is running, the header is disabled.
- Output language: a pop-up on the right of the header with a globe icon: "Same as Text" (the default, "Auto" on the button), English (US), English (UK), Russian, German, Spanish. The choice rechecks the latest version and adds a new card; if the language differs from the text's, the model translates. The panel opens with "Auto"; once Context has been read, the pop-up switches to the conversation's language by itself before Check, whatever the draft's language (02 M7, 04 §4.5); if the user has already chosen a language, we leave it. The language isn't remembered for the app.
- ✕ closes the panel.

### 2.3a Context

Context, which is what the user is replying to, sits above the text: that way the panel reads top to bottom, like a conversation. The section takes one line and doesn't inflate the panel. Context is input only: text, images, 📷. It has no check buttons of its own; the check is started by the action button next to the dialog field (§2.7).

- Collapsed, with content: `▸ Context` + the first line of the context text (truncated with an ellipsis) + 30×22 image thumbnails + the 📷 button. A click on the line expands it.
- Before the first check: expanded; the feed has the "Text to check" card (§2.4). The cursor is in the context field if the text was captured, otherwise in "Text to check". Changing the type, tone and level doesn't start a check. After Check the section collapses.
- Context reading (02 C6): if the text was taken from an app window, Cyrano captures that window right away and fills the field with a description of the conversation: who it's with, the language, what it's about, the format, the style, the formality (04 §4.5); it puts the conversation language into the language pop-up if the user hasn't chosen one. The screenshot isn't added as a thumbnail: only text goes into the context. Without Screen Recording, automatic context reading doesn't run: only manual input and copy-paste (decided 2026-11-06). There's no screenshot, no call, no status line and no system prompt; the field stays open for typing, ⌘V and dropped images, and 📷 asks for the permission as an explicit action (below).
- Reading status: a dimmed line in the title row, between "Context" and 📷; the field holds only the context itself. While there's a status, it shows instead of the collapsed summary.

  | State | Line |
  |---|---|
  | Reading (Check disabled) | indicator + "Reading the conversation…", from 3 s on "… 7 s", a Skip link |
  | Read | nothing: the lines are in the field |
  | No conversation in the screenshot | "No conversation found in this window" |
  | 20 s timeout | ⚠ "Reading took too long" Try Again |
  | No network | ⚠ "Couldn't reach OpenAI" Try Again |
  | Not signed in / plan limit | ⚠ "Couldn't read: not signed in to ChatGPT" / "…: plan limit reached", without Try Again |
  | Another error, an answer off the schema | ⚠ "Couldn't read the conversation" Try Again, details in the tooltip |

  Skip cancels the call, and Check becomes available right away: the check goes without context. Try Again reads the same screenshot again. The line disappears when the user types in the Context field (that cancels reading too) and on Check. Closing the panel cancels reading.
- Collapsed, empty: `▸ Context` + the dimmed hint "Add who you're writing to" + 📷.
- Expanded: a field of a fixed height, about 3 lines, that scrolls inside, below it 56×38 thumbnails with ✕ and the caption "or paste ⌘V / drop images · 2 images". The text is edited right in the field: you can add anything by hand.

```
├──────────────────────────────────────────────────────────────┤
│ ▾ Context                                                  📷 │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ Ravi: Hi Alex, when you were off last week, I noticed    │ │
│ │ that some PRs weren't tagged…                            │ │
│ │                                                          │ │
│ └──────────────────────────────────────────────────────────┘ │
│ [▭]ˣ [▭]ˣ  or paste ⌘V / drop images · 2 images              │
├──────────────────────────────────────────────────────────────┤
```

- Thumbnails: a click selects a thumbnail and opens Quick Look, a large preview; Space on a selected thumbnail opens and closes it. That way you can tell similar screenshots apart before deleting the extra one.
- Images: 📷 captures the active window of the source app; you can also paste with ⌘V or drag a file onto the panel. There's no hard limit; after 10 images the caption warns that the check will get slower and more expensive. If there's no Screen Recording yet (context reading was turned off in onboarding), the first press of 📷 brings the system prompt, preceded by one line: "To see the conversation you're writing in, Cyrano needs to capture this window once." Pasting and dragging need no permission. If the text was typed or pasted in the panel (desktop, Check Text…, Check Clipboard), there's no source window and 📷 isn't shown; pasting and dragging work. ⌘V with an image on the clipboard adds it to the context with any focus in the panel and in any keyboard layout.
- Changing the context (text, adding or removing an image) doesn't restart the check by itself: the button next to the dialog field becomes Check again if the field is empty, and Send sends the message together with the new context (§2.7).
- To collapse it back, click `▾ Context`.

### 2.4 Feed: a chat with version cards

The panel is a chat. Every variant of the text from the model is a card; the user's messages and the answers to questions are bubbles between the cards. There's no separate navigation between versions: the history is the scrolling feed.

- "Text to check" is the card before the first check. Its text can be edited: correct what was captured or type text from scratch. If no text was captured (desktop, Finder, Check Text…), the card is empty, with a cursor and the hint "Select text in any app and press ⌥⌘G, or type or paste it here". After Check the card becomes read-only, and Version 1 appears next.
- Order: Version 1 (the first check) → a message → Version 2 → … New items appear at the bottom, and the feed scrolls to them. The feed grows with the panel up to 70% of the screen height, after that only the feed scrolls; the header, Context and the input field stay in place.
- A user's message is a bubble on the right (accent color), shown whole, wrapped to the width. An answer to a question is a bubble on the left, without a new card.
- Your own version ("check my version: …") is shown as the whole message, and the corrected variant is the next card.

#### Version card

- Header: "Version N".
- The action sits inside the card, on the summary line on the right: Copy. That way it's always clear which variant gets copied. On the latest card Copy is the default button (accent color), on earlier ones a regular button. Copy puts the card's variant on the clipboard, and the panel stays open; the user pastes it (02 C3).
- The text with a diff against the previous card (Version 1 against the source), the system font at 14 pt; the text can be selected and copied. Removed text is struck through and dimmed (`secondaryLabelColor`); added text has a solid underline and a `systemGreen` 20% background; `style` changes have a dashed underline and a `systemBlue` 15% background. The line style backs up the color.
- Below the text, one summary line: "▸ 5 fixes · 1 style suggestion" (or "▸ 1 change", "✓ No changes needed"; a translation shows "Translated to German" and no list, 04 §2). A click expands the list of changes.
- The list of changes: an icon (● error, ◇ style), then in a column on the right `before → after` (monospaced, long changes wrap) and the reason; on the right, ✕ "reject". Rejecting creates a new card locally, without calling the model. Until Explain arrives, the summary says "Explaining…"; if it failed, the changes are shown without reasons.
- A card can't be edited: changes are requested with a message.
- VoiceOver reads a change as "this, replaced with these, error" / "… style suggestion"; the card is announced as "Version 2, 1 change".

#### Dictionary from a card

- Select a word or a phrase in the text of a version card or in "Text to check" → the context menu (right click or ⌃-click) → Never Change “…” as the first item, above the system ones. Spaces, punctuation and quotes at the edges of the selection are dropped; a selection across a line break doesn't count as a term. For a word that's in the dictionary, the menu shows "Remove “…” from Dictionary". At the bottom of the panel, the line "“Bitbucket” added to Dictionary." (or "“…” removed from Dictionary.") with Undo. It applies from the next request; from "Text to check", already on the first check: the terms are looked up in the text on Check.
- "Text to check" is editable, so the item is added to the text field's menu and keeps it: Cut, Copy, Paste, spelling and the other system items stay below it.
- The same item is in the context menu of a change row of the latest card ("Never Change “k8s”"): it rejects the change and adds the former word in one action. Adjacent changes are merged (`kibana, take → Kibana. Take`, 04 §2), so there's a separate item for each former word that isn't in the new text as is: "Never Change “kibana”", "Never Change “take”". If a change only inserted words, there are no items. The menu opens anywhere on the row. Undo removes the term from the dictionary; the rejected change stays as a card in the feed.

### 2.7 Bottom

The dialog field across the full width, below it one status line: the token indicator and short messages ("“Bitbucket” added to Dictionary." with Undo, "Copied."). There are no buttons here: Copy lives in the cards. Captions and the status don't wrap: a long status is truncated with an ellipsis, the full text is in the tooltip.

- The token indicator `1.2k tokens`: the sum of `usage` of all calls in this panel, context reading included; one number, no breakdown. If the subscription limit is exhausted, a red "Plan limit reached".
- The dialog field appears after the first check: before it there's nothing to talk about, and a disabled field with a hint confuses. Multi-line, a fixed height of 2 lines, then it scrolls inside: short messages fit, and the panel doesn't jump. ↩ inserts a line break. The placeholder is "Ask or tell what to change… (any language)". A new message applies to the latest version.
- The action button to the right of the field is the only one in the panel; there's no other check button. It's a regular text button; its look doesn't change, only its label does:

  | State | Label | What it does |
  |---|---|---|
  | Before the first check | Check | the first check with context; there's no dialog field yet; disabled while the text is empty or context reading is going on |
  | After, context unchanged | Send | sends the message; disabled when the field is empty |
  | After, context changed, field empty | Check | rechecks the latest version with the new context |
  | After, context changed, a message in the field | Send | sends the message together with the new context |

  While a check is running, the button is disabled. "Context changed" means the text or the images differ from what was sent in the last request.

### 2.8 Panel states

| State | What is shown |
|---|---|
| Empty text | the "Text to check" card is empty and editable, with the cursor in it (§2.4) |
| Checking | the next version card with a thin progress bar; the previous text is dimmed until the new one streams in |
| Result | see the layout |
| Dialog turn | the message as a bubble and "…" for the answer; the action button and the header are disabled until it ends |
| Network error / timeout | "Couldn't reach OpenAI." [Try Again] [Copy Original] |
| Limit | "Your ChatGPT plan limit for this app is reached." [Copy Original]; a link to the limit settings |
| Not signed in / token revoked | "Sign in to ChatGPT to check text." [Continue with ChatGPT] |
| No Accessibility | text is taken only with ⌘C from the selection or typed in the panel; the header shows a ⚠︎ icon with the tooltip "Grant Accessibility to read text directly" |

### 2.9 Keyboard

There's one shortcut of its own, Check text, ⌥⌘G by default; it works globally and is changed in onboarding and in Settings → General → Shortcut (02 T6). Inside the panel there are no shortcuts of its own; actions are done with buttons.

System keys: ↩ inserts a line break in fields, Esc closes the panel, Tab moves between elements, ⌘C copies the selection, ⌘V pastes text or an image (§2.3a), ⌃-click / right click on a selection in a card or in "Text to check" opens the context menu with Never Change.

## 3. Check Text… and Check Clipboard

There's no separate window. Check Text… opens the same panel in the center of the screen with an empty "Text to check" card (§2.4). Check Clipboard opens it with the text from the clipboard; if there's no text on the clipboard, with an empty card. The source is "Manual", and there's no context reading.

## 5. Settings

A 600 pt wide window (so the Per-app defaults table in Style fits) with a standard non-customizable toolbar of five tabs — General, Style, Dictionary, Prompts, Account (icon + label); the content is a SwiftUI `Form` with the `.grouped` style: rounded sections, label on the left, control on the right, rows of 40–44 pt, toggles as `Toggle` switches, drop-down lists as standard regular-size pop-up buttons; the window title is the name of the active tab; the last used tab opens; the minimize/zoom buttons are disabled. Settings are kept to a minimum: everything about the current check (type, tone, level, context) is changed in the panel itself.

### General

- Show in menu bar.
- Launch at login (`SMAppService.mainApp`). The status comes from the system; if macOS requires approval, an "Open System Settings…" line to Login Items; an error shows as a line below the toggle.
- Read context from the window: on by default. When called from an app, Cyrano captures the window and fills Context (02 C6). Caption: "A screenshot of the window goes to OpenAI to find who you're writing to, what about and in which language."
- Models: three pop-ups with `gpt-6.1-sol`, `gpt-6.1-terra`, `gpt-6-luna` (02 M1), with a caption under each name: Read context — "Describes the conversation from a screenshot" (Terra by default); Proofreading — "Checks and the dialog" (Sol); Explanations — "Reasons for each change" (Sol).
- Shortcut: recording the "Check text" shortcut (⌥⌘G by default); a conflict with a system one shows a warning below the field.
- Permissions: a status line for Accessibility and Screen Recording with an "Open System Settings…" button. There are no toggles of our own for system permissions.

### Style

- Custom instructions: a multi-line field, free text.
- Per-app defaults: an "App · Context · Tone · Level" table (the app's icon and name; text typed in the panel is the "Manual" row). It has no language: the language isn't remembered for the app (02 M7). It fills itself from the panel header. The − button and Delete remove the selected rows; removing resets the app to the general defaults Message · Neutral · Fluency. Caption: "Filled from the Proofreading panel. Removing an app resets it to Message · Neutral · Fluency."

### Dictionary

A separate tab, because the dictionary grows along the way and can be large (hundreds of terms), while Style holds settings that rarely change.

- A "Search N terms" search field at the top.
- A `Term · Added` table, sorted by clicking a column header, newest first by default. A double click edits the term in the "Edit Term" sheet.
- Below the table, the standard + / − buttons: + opens the "Add Term" sheet with a field, − and Delete remove the selected rows. A term that's already in the dictionary in any case isn't added: the sheet shows "This term is already in the dictionary."
- Import… / Export… — a text file, one term per line; on import, empty lines and duplicates are skipped, and next to the buttons the caption "Imported N terms." appears.
- A hint in the bottom line: "Add terms from the Proofreading panel: select a word and choose Never Change."

### Prompts

- What it is: the instruction texts the app sends to the model. There are two kinds:
  - Pipeline — whole call prompts: Proofread (the main instruction of every check), Explain Changes (writes the reasons for changes), Classify Request (decides whether your message is a question or a request to change the text), Read Context (who is in the conversation and what you're replying to, from a screenshot);
  - fragments — Text Types (Message, Email, Docs), Tones, Levels: short lines substituted into Proofread for `{type}`, `{tone}`, `{level}` when that value is selected in the panel.
- On the left, a list by these groups; modified ones are marked "•", below the list the legend "• Modified".
- On the right, below the title, what the prompt does ("Main instructions for every check", "Inserted into Proofread as {type} when this type is selected in the panel").
- On the right, an editor for the selected prompt in a monospaced font, below it the list of available placeholders (`{type} {tone} {level} {language} {customInstructions}`), "Changes apply to the next check." and the "Restore Default" button.
- Saved automatically; the built-in version isn't lost.

### Account

- "Signed in as name@email".
- Tokens for the app session (the sum of `usage`).
- [Sign Out] — a regular button (not the default one): revoke + delete from Keychain, then onboarding.
- A "Manage app usage limit" link to the ChatGPT settings page.

## 6. Interface texts

The interface is in English, Spanish and Russian; the language follows the system (System Settings → General → Language & Region, or the app's own language there), and any other language gets English. More languages are added later. The texts live in a String Catalog, with English as the source. Spanish is Castilian (castellano), the Spanish of Spain, with the words of Apple's Spanish macOS for Spain ("ordenador", "Ajustes del Sistema"); it goes into the catalog as `es`, so Spanish from any region gets it rather than English. The model's explanations are in the interface language. The corrected text itself can be in any language (§2.3).

In English, buttons and menu items are in title case ("Try Again", "Copy Original"), messages and hints in sentence case with a period; Spanish and Russian use sentence case everywhere, as their system interfaces do. Short phrases, no exclamations. Errors always say what to do next.

## 7. Accessibility

Accessibility is always a priority. Every function of the app works with VoiceOver and with the keyboard alone: the panel, onboarding, Settings and the menu. A function that needs a mouse, a right click, dragging or hovering also has a way through the keyboard and VoiceOver. A new screen or control ships accessible, or the package isn't done.

- All controls are reachable from the keyboard, Full Keyboard Access included; the Tab order is Context → feed cards (summary, Copy) → the dialog field.
- All icon buttons (📷, ✕, reject, remove an image) have an accessibility label; the ⚠ icons have a label with what to do.
- The feed is a `log` region. VoiceOver announces a new card ("Version 2, 1 change"), an answer to a question, an error and the end of context reading; status messages ("Copied.", "“k8s” added to Dictionary.") are announced too, in full even when the line truncates them.
- A version card reads as its text, without the removed words; the changes are read from the list (§2.4). Never Change and Remove from Dictionary are in the VoiceOver actions of a change row and of a selection, the same as in the context menu.
- Images: dragging has ⌘V and 📷 as alternatives; a thumbnail is focusable, Space opens Quick Look, and the remove button is reachable.
- Settings tables (Per-app defaults, Dictionary) are navigable and editable from the keyboard: selection, Delete, the + / − buttons, editing a term.
- Text contrast ≥ 4.5:1 on the diff backgrounds in both themes and with Increase Contrast.
- No animations; streaming text is turned off with Reduce Motion (the text is shown whole when ready).
- Checking: every package that changes the UI goes through its screens with VoiceOver and Accessibility Inspector before it's done.

## 8. Review against the Apple HIG

Source: the HIG sections Panels, The menu bar (Menu bar extras), Settings, Keyboards, Privacy, Onboarding, Accessibility, Color, Buttons, Menus, Windows (2026-10-27).

| HIG rule | How it was | Decision |
|---|---|---|
| Panels: a short noun title, a title bar for dragging, no minimize button | no title | The title "Proofreading — <app>", a titled utility panel, only "close" |
| Panels: simple controls are preferred, text input is discouraged | the dialog and Context are text fields | A deliberate deviation: the dialog is a key scenario. The precedent is Writing Tools with its "Describe your change" field |
| Panels hide when the app is inactive | the panel is visible on top of another app | A deliberate deviation: the whole point is working on top of the active app; the behavior matches Writing Tools and Spotlight |
| Don't reassign standard shortcuts | ⌘[ / ⌘] for versions (the standard is alignment) | No navigation between versions: the feed scrolls. No shortcuts of its own inside the panel; the global ⌥⌘G isn't taken in the standard table |
| Color isn't the only way to convey meaning | error/style differed only by green/blue | Solid/dashed underline, ● / ◇ icons, text group headings |
| Menu bar extra: a menu rather than a popover; a template symbol; the user decides whether the icon shows; don't rely on it being there | the icon always shown | The "Show in menu bar" toggle; launching again opens onboarding with this toggle |
| Ask for permissions only when needed, with a clear explanation | Accessibility in onboarding, Screen Recording on the first 📷 | Accessibility in onboarding: it's needed for the main function, explained in one sentence.
