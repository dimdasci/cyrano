# 01. Варианты реализации и UX

Статус: **исторический черновик**. Требование «только локальная модель» снято: движок — подписка ChatGPT ([02](02-tech-decisions.md) T7), разделы про ограничения Foundation Models ниже устарели. Варианты «исправить молча» и «живые подчёркивания» отклонены и удалены. Дата: 2026-10-27.

## Цель

Нативное приложение macOS, аналог Grammarly для английских сообщений:

- берёт текст из активного поля ввода (браузер, мессенджер, почта) без копипаста;
- исправляет грамматику, орфографию, пунктуацию, стиль;
- коротко объясняет, что и почему изменено;
- даёт настроить стилистику;
- по возможности учитывает контекст: предыдущие сообщения, скриншот окна;
- работает **только на локальной Apple Foundation Model**.

## Что проверено на этой машине

macOS 27.0.1, Xcode 27.1, Swift 6.4. Пробный запуск `FoundationModels`:

| Параметр | On-device `SystemLanguageModel` | `PrivateCloudComputeLanguageModel` |
|---|---|---|
| Доступность | available | available |
| Guided generation (`@Generable`) | да | да |
| Vision (картинки на вход) | **да** | да |
| Контекст | **4096 токенов** (вход + выход) | 32768 |

Выводы:

1. **Скриншот можно отдавать модели напрямую** (`Transcript.ImageAttachment`), без OCR. OCR через Vision остаётся запасным вариантом: он дешевле по токенам.
2. **Главное ограничение: 4096 токенов.** В них должны уместиться инструкции, стиль, контекст, исходный текст и ответ (исправленный текст плюс объяснения, то есть ответ больше входа). На практике текст для проверки примерно до 1000–1200 слов, контекст надо резать и сжимать. Длинные тексты бьём на абзацы.
3. Private Cloud Compute не локальный, поэтому по умолчанию он **выключен**. Его можно добавить позже как явную опцию ради качества модели (см. 02, T7).
4. Модель маленькая (~3B). Грамматику и тон исправляет хорошо, но иногда «переписывает лишнее» или ошибается в объяснениях. Поэтому diff считаем **сами**, детерминированно, а от модели берём только исправленный текст и пояснения к правкам.

## Ключевая техническая проблема: забрать текст и вставить обратно

Наше приложение полностью нативное (Swift, SwiftUI/AppKit). Chrome, Electron и web-поля ниже относятся к **чужим приложениям**, в которых пользователь пишет текст и из которых мы его забираем. Как именно забирать текст, зависит от того, на чём написано это чужое приложение.

| Способ | Как работает | Плюсы | Минусы |
|---|---|---|---|
| **A. Accessibility API** (`AXUIElement`) | Читаем `kAXFocusedUIElement` → `kAXSelectedText` / `kAXValue`; пишем через `kAXSelectedText` или `kAXValue` | Без буфера обмена, видно выделение и курсор, можно читать соседние элементы окна (история чата) | В Chrome и Electron-приложениях (Slack, Discord, VS Code) нужен `AXManualAccessibility` / `AXEnhancedUserInterface`; запись в web-поля (contenteditable) часто не работает |
| **B. Эмуляция ⌘A/⌘C → ⌘V** (`CGEvent`) | Копируем, исправляем, вставляем, восстанавливаем буфер обмена | Работает почти везде | «Мигает» выделение, временно трогает буфер обмена, ⌘A в некоторых мессенджерах выделяет не то |
| **C. macOS Services** (контекстное меню «Check Grammar») | Система передаёт выделенный текст и принимает замену | Без разрешений, официальный путь | Только выделенный текст, без истории и окна, поддерживается не везде (Electron плохо) |

**Предложение:** гибрид **A → B fallback**. Сначала читаем через AX. Если не вышло или поле web-шное, используем буфер обмена. Обратно вставляем так же: AX-запись, при неудаче ⌘V с восстановлением буфера. Services можно добавить почти бесплатно как третий вход.

Следствие: Accessibility недоступен из App Sandbox, поэтому **приложение распространяется вне App Store** (Developer ID или просто локальная сборка). Нужны разрешения *Accessibility* и, для скриншотов, *Screen Recording*.

## Варианты UX

### UX-1. Горячая клавиша → плавающая панель (рекомендую для MVP)

```
Пишу в Slack → ⌥⌘G → рядом с полем появляется панель:
┌──────────────────────────────────────────────┐
│ I ~~has~~ **have** sent ~~it~~ **the file** yesterday.   │
│                                              │
│ • has → have: подлежащее «I» требует have    │
│ • it → the file: уточнил, что именно         │
│                                              │
│ ‹ v1 of 1 ›   Тон: [Casual ▾]  [Message ▾]  📷    │
│ > make it softer, this is my manager_        │
│              ⌘↩ Вставить  ⌘C Копировать  Esc │
└──────────────────────────────────────────────┘
```

- Текст подменяется в поле только после подтверждения (⌘↩).
- Результат можно дорабатывать в диалоге: пожелания, своя версия, вопросы (см. 03, S1a).
- Можно отклонить отдельную правку кликом.
- Переключатель тона прямо в панели перегенерирует результат.
- Похоже на Raycast/Spotlight, `NSPanel` без активации чужого окна.

### UX-4. Окно-редактор в menu bar

Иконка в строке меню открывает окно «вставь текст → получи исправление». Нужен как запасной путь и для длинных текстов. Почти бесплатен, раз ядро уже есть.

## Контекст

| Уровень | Источник | Стоимость |
|---|---|---|
| К0 | Только сам текст | — |
| К1 | Название приложения и окна (Slack / Mail / Chrome «Gmail») → автоматический выбор профиля стиля | Почти бесплатно |
| К2 | Текст окна через AX: последние N сообщений чата, тема письма | Средне, зависит от приложения, в web-приложениях работает нестабильно |
| К3 | Скриншот активного окна (ScreenCaptureKit) → модели как картинка или через OCR | Нужно разрешение Screen Recording, тратит токены (картинка съедает заметную часть из 4096) |

Предложение: К0+К1 в MVP, К3 по кнопке «📷 с контекстом» в панели (явно, не всегда), К2 позже для пары приоритетных приложений.

## Настройки стиля

- **Пресеты:** Neutral · Casual (чат) · Professional · Friendly · Concise.
- **Уровень вмешательства:** только ошибки / ошибки + естественность / свободная перефразировка.
- **Вариант английского:** US / UK.
- **Свои инструкции** свободным текстом («не ставь Oxford comma», «я пишу коллегам-инженерам»).
- **Профили по приложениям:** Slack → Casual, Mail → Professional.
- **Словарь «не трогать»:** имена, термины, сленг.
- **Язык пояснений:** русский / английский.
